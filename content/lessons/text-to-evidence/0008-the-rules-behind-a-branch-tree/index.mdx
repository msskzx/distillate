## 1. Three ways to compare a word

Everything else in this lesson follows from one fact. The code compares two words in three different ways, two
for building trees and one for grading, and each part of the feature picks one of them.

| Name in the code | What it removes or folds | So these count as equal | Used by |
| --- | --- | --- | --- |
| `normalizeWord` (<RepoLink repo="namaq" path="src/lib/quran/normalize.ts" />, lines 2 to 12) | every vowel mark, shadda, sukun, dagger alif, maddah, tatweel and Quranic sign; folds أ إ آ ٱ to ا, ى to ي, ة to ه | إِنِّى, إِنِّىٓ and أَنَّىٰ (all become اني) | opening groups, phrase ids and `?o=`, pieces, the phrase tree |
| `spell` (line 98) | tatweel and word joiner, the signs U+06D6 to U+06ED, a shadda on the first letter, a sukun on the last letter. Keeps every other mark | لَهُمْ and لَهُم; مَّتَـٰعًۭا and مَتَـٰعًۭا | the drawn tree, the first-word column, `?w=`, quiz trees |
| quiz `letters` (<RepoLink repo="namaq" path="src/lib/quiz/branchAnswers.ts" />, line 10) | like `normalizeWord`, and also folds the hamza seats | everything a reader can type for one word | grading typed answers |

On top of the first two, a **root guard** (lines 85 and 86) adds the word's root from the Quranic Arabic Corpus to
the key. Two words with the same letters but different roots, or one rooted and one rootless, never share a group
or a node. In the whole dataset only one phrase id belongs to two root groups: `قال رب اني` is split into قَالَ رَبِّ إِنِّى (7
ayat, rootless إنّي) and قَالَ رَبِّ أَنَّىٰ (2 ayat, root أ ن ي).

<Callout tone="note" title="Two statements of the grouping rule">
The plan (<RepoLink repo="namaq" path="docs/plans/quran-shared-openings.md" />, line 89) says on purpose that
"diacritics and the alif and ya spellings do not separate two openings". The owner's later wording is "words match
with diacritics removed". The code follows the plan, so it also folds ى into ي and the hamza seats on alif into a
bare alif, and أَنَّىٰ and إِنِّى have the same letters as far as grouping knows. Only the root guard keeps them apart.
</Callout>

Every mark `spell` removes, `normalizeWord` removes too, so the letters key is always the looser of the two. A
word that differs only in kept marks is one word to search and two words to the tree. Across all 3,140 ayat,
1,293 letter forms are written with more than one `spell` spelling. Most of those differences are a short vowel
or tanween (1,101 forms involve one), 255 involve a maddah and 121 a dagger alif; a form can count under more
than one mark.

| Part | Compares by | Size on the whole dataset |
| --- | --- | --- |
| Grouping (`sharedOpenings`) | letters and root | 816 openings over 3,140 ayat, 259 of them with more than one first-word spelling |
| Phrases (`listPhrases`) | letters and root | 1,774 phrases |
| Pieces (`pieces`) | letters and root | 935 pieces |
| Drawn tree and quiz tree (`branch`) | `spell` and root | one node per spelling |

## 2. Building the data

`npm run quran:branches` runs <RepoLink repo="namaq" path="scripts/quran/buildBranches.ts" />. It reads the 604 reader
pages, the same text `/quran/read` shows.

1. `readerAyat` (line 29) splits the pages into ayat and drops tokens that are only marks, such as pause signs and ۞.
2. `conjunctions` (line 57) and `withConjunctions` (lines 61 to 69) mark an ayah `conj: "و"` or `"ف"` when the corpus splits a `w:` or `f:`
   prefix off its first word. The oath و (`w:P`, the `(?!P\+)` on line 57) is not a conjunction, so وَٱلْفَجْرِ keeps its و.
3. `withRoots` (lines 71 to 83) stores each word's root, and fails the build when a word has no STEM annotation.
4. `sharedOpenings` (line 131) keeps only ayat whose opening another ayah shares.
5. `withNext` (lines 255 to 261) attaches the next ayah of the same surah to every ayah that "continues" (section 6).

## 3. Grouping ayat into openings

- An ayah's opening id is its first **two** words after `normalizeWord`, with a joined و or ف removed first
  (`openingId`, line 128; `stem`, line 110). An ayah of one word has no opening.
- Ayat with the same id and the same roots for those two words form a group (`sharedOpenings`, lines 131 to 142). A
  group needs two ayat.
- So يَطُوفُ عَلَيْهِمْ and وَيَطُوفُ عَلَيْهِمْ are one group, and so are قَالَ رَبِّ and قَالَ رَبُّ: the letters match and
  both رب carry the root ر ب ب.

## 4. Drawing the tree

`branch` (line 282) draws a group as `grow(grown(shown(ayat)), 0, spell, ...)`.

- **The node key** is `[spell(word), root]` (`wordKey`, line 86). A node takes words while every ayah under it has
  the same key at that position, and stops at the first position where the keys differ or an ayah ends
  (`grow`, lines 263 to 280).
- **Every mark counts, with three exceptions**, all inside `spell`. Removed before comparing: the signs U+06D6 to
  U+06ED (small high and low letters, pause signs, the iqlab meem), a shadda on the first letter (it comes from the
  word before), and a sukun on the last letter (option D, so لَهُمْ and لَهُم share a node and لَهُمُ does not).
- **Children** keep the order in which their first ayah appears in the group, which is mushaf order.
- **An ayah that ends at a node** is listed on that node, even when the node has children.
- **What the node shows** is `plain` (lines 100 to 104): at each letter, only the marks every ayah has. Merged
  nodes whose originals differ carry `forms`, which drive the amber context button.

## 5. A leading و or ف, and the first-word column

- `split` (line 120) asks whether the first words of a group differ under `spell`. If they do, `shown` (line 122)
  replaces every ayah's first word with the first ayah's first word without its و or ف, so the tree is built from
  one shared first word.
- `variants` (line 286) then draws one box per `spell` spelling of the first word (يَطُوفُ, وَيَطُوفُ), coloured
  green for و and purple for ف. A box links to `?w=<spelling>`, the tree of only those ayat (`spelledAs`, line 297).
- This also fires when the first words differ only in marks (لَقَدْ and لَّقَدْ), because the test is `spell`, not the
  presence of a conjunction.

## 6. Next-ayah leaves

- `continues` (line 249) is true when an ayah's words, compared by `[spell, root]`, are the beginning of a longer
  ayah in the same group.
- At build time such an ayah gets `next`, the words of the following ayah in its surah (line 259). At draw time
  `grown` (line 253) appends ﴿n﴾ and those words, so the ayah ends at a leaf: 56:17 ends with ولدان مخلدون and
  continues ﴿١٧﴾ بأكواب وأباريق وكأس من معين.
- Only one following ayah is added, and only inside the same surah. The build decides `next` against the two-word
  group, the page checks `continues` again against the ayat actually drawn.

## 7. Phrase search, `?o=`, `?r=` and `?w=`

- `listPhrases` (lines 175 to 247) lists every phrase the page can open. It takes each opening, every node of each
  opening's `phraseTree` (the letters-only tree, line 284) that holds two ayat or more, and every inner node of the
  drawn tree that has a parent and children. In a group that mixes و and ف it also walks each exact spelling on its
  own. A last loop splits an existing id in two when its ayat fall into two root groups. Ids are `normalizeWord` text.
- The page (<RepoLink repo="namaq" path="src/app/quran/branches/page.tsx" />, lines 47 to 55) takes `?o=` as a
  phrase id. When two phrases share the id (only `قال رب اني` does), it offers both and needs `?r=` (the roots) to
  choose. `startingWith` (line 169) then takes every ayah that opens with the phrase, with or without its و or ف.
- `?w=` narrows the group to one first-word spelling before drawing.

## 8. Pieces, the list view

`pieces` (lines 329 to 366) cuts each opening into pieces of at most `PIECE_MAX` = 6 ayat. It walks the
**letters-only** `phraseTree`, not the drawn tree:

- a node with six ayat or fewer is a piece;
- a larger node stays one piece when none of its children holds two ayat;
- a larger node mixing و/ف spellings is split into one piece per spelling.

## 9. The quiz

`branchQuestions` (<RepoLink repo="namaq" path="src/lib/quiz/branchQuestions.ts" />) makes one question per piece
of six ayat or fewer, then draws that piece with `branch`, the **marks** tree (line 31). It skips the question when
that tree's root has fewer than two children or ends an ayah (line 32). The prompt shows the root's words, the
first-word spellings if any, and the number of children. Grading (`matchTreeAnswers`) compares typed letters only:
an inner node needs all its words, a leaf its first two, and sibling subtrees of the same shape may be swapped.
It yields 872 questions over the whole Qur'an.

## 12. Every same-letter split in the dataset

To see whether the example is an exception or a pattern, the analysis walked every opening's drawn tree and
collected each pair of sibling nodes whose first words have the same letters (`normalizeWord`) but different
`spell`. There are 196 such pairs. Each falls in one of four kinds:

| Kind | Pairs | Examples | Source of the mark |
| --- | --- | --- | --- |
| maddah on the last long vowel (U+0653, or آ) | 112 | إِنِّى/إِنِّىٓ, مُوسَىٰ/مُوسَىٰٓ, ٱلَّذِى/ٱلَّذِىٓ (38/13 ayat after هُوَ), مَا/مَآ, كَفَرُوا۟/كَفَرُوٓا۟, تَتَّخِذُوا۟/تَتَّخِذُوٓا۟ | next word starts with a hamza |
| dagger alif on a final ى | 7 | مُوسَى/مُوسَىٰ, إِلَى/إِلَىٰ, عَلَى/عَلَىٰ | next word starts with a hamzat wasl |
| a vowel where the other has none | 44 | لَهُم/لَهُمُ, مِن/مِنَ, عَن/عَنِ, قُلْ/قُلِ, قَالَت/قَالَتِ | joining vowel before a hamzat wasl |
| a different word or case | 33 | رَبِّ/رَبُّ, إِن/إِنَّ, ٱللَّهُ/ٱللَّهَ, كَذَّبَتْ/كُذِّبَتْ, جَنَّـٰتُ/جَنَّـٰتٌ | the word itself |

Only the last kind is a difference in the word. The first three are all marks the neighbouring word puts there.

In the quiz, 151 of the 872 questions have two branches at their first split that the reader must type with the
same letters. Ignoring a maddah on the last long vowel (including the وٓا۟ endings) would merge those two branches
in 94 of them, and ignoring a final dagger alif as well, in 96. In 95 questions every same-letter pair would merge.

## 13. Gaps and contradictions to decide

Each item names what the code does, the rule it meets or breaks, and a question for the owner. None is fixed here.

1. **The maddah from a following hamza still splits nodes.** 112 of 196 same-letter pairs. The rule from
   2026-10-21 says marks that come from the neighbouring word do not count, and the code lists only three. The
   maddah on a word's last long vowel (إِنِّىٓ, مُوسَىٰٓ, ٱلَّذِىٓ, قَالُوٓا۟) is in the same family. A maddah inside a word
   (جَآءَ, ٱلسَّمَآءِ) belongs to the word and is a different case. *Should a final maddah stop counting?*
2. **The docs contradict item 1.** <RepoLink repo="namaq" path="docs/quiz-ayah-branches.md" /> (line 28) names
   تَتَّخِذُوا۟ and تَتَّخِذُوٓا۟ as the example of nodes that stay separate. That pair differs only by a maddah from the
   next word. If item 1 changes, this example changes with it.
3. **The dagger alif dropped before a wasl splits nodes.** 7 pairs, such as مُوسَى/مُوسَىٰ. Same family as item 1.
   *Should a final dagger alif stop counting?*
4. **The joining vowel before a wasl splits nodes, by the owner's choice.** 44 pairs. Option D kept لَهُمُ apart
   from لَهُم. By origin it is a neighbour's mark like the dropped sukun. *Keep option D as it is, or extend it?*
5. **Groups, phrases and pieces use letters; the tree and the quiz tree use marks.** Consequences seen above: the
   `قال رب` page shows a phrase that its tree does not have as one node; قَالَ رَبِّ إِنِّى is a piece of 7 that the quiz
   skips, though the page draws 5 and 2; the quiz question for قال موسى shows only «قَالَ» as its opening, because
   the marks tree splits right after it. *Should pieces and the quiz cut on the same key as the drawn tree?*
6. **"Diacritics removed" is narrower than the code.** The plan chose to fold the alif and ya spellings, and `normalizeWord` folds ى into ي and أ إ آ ٱ into ا. أَنَّىٰ and
   إِنِّى then share letters, and only the root guard separates them. ء ؤ ئ are not folded, so the id is
   `ولقد ءاتينا موسي`, while the suggestion box tolerates hamza spellings. *Is ى against ي a letter difference that
   should keep two words apart in the grouping key, or does the plan's folding stand?*
7. **A quiz question can ask for the same letters twice.** 151 questions. The grading pairs such branches by what
   follows, so they can be answered, but the reader sees two fields for one word. It goes away entirely for 95 of them if
   items 1 and 3 change.

## 14. How to close the gaps

These are proposals, not changes. The numbers come from applying each one to a scratch copy of the code and
running it on the same data.

**Fix A: two more context marks in `spell` (items 1 to 3).** After the existing three removals, `spell`
(line 98) would also drop a maddah on the last pronounced letter (`\u0653` at the end, or before a final silent
alif as in قَالُوٓا۟) and a dagger alif after a final ى. A maddah inside a word (جَآءَ) stays. The one-line change:

```ts
.replace(/\u0652$/u, '').normalize('NFD')
  .replace(/\u0653(?=\u0627?$)/u, '')
  .replace(/(\u0649)\u0670$/u, '$1')
  .normalize('NFC')
```

Measured effect:

| | Now | With fix A |
| --- | --- | --- |
| Same-letter sibling pairs in all trees | 196 | 75 (the 44 joining vowels and the real differences) |
| Quiz questions with a same-letter pair at the first split | 151 of 872 | 56 |
| Quiz questions with a same-letter pair anywhere | 163 | 64 |
| `?o=قال+رب` | إِنِّى (5) and إِنِّىٓ (2) | one node إِنِّى (7) |
| `?o=قال+موسي` | مُوسَىٰ (5) and مُوسَىٰٓ (3) | one node, root reads قَالَ مُوسَىٰ (8) |
| `?o=ولقد+ءاتينا` | ءَاتَيْنَا / ءَاتَيْنَآ, then مُوسَى / مُوسَىٰ | ءَاتَيْنَا (15), then مُوسَى (10) |

رَبِّ / رَبُّ, إِنَّ / إِنِّى and أَنَّىٰ stay apart, as they should. The merged nodes keep each ayah's own
spelling in `forms`, so the amber context button shows the maddah where it was. Three things move with the
change. One quiz test fails as expected: <RepoLink repo="namaq" path="src/lib/quiz/branchQuestions.test.ts" />
asserts that تَتَّخِذُوا۟ and تَتَّخِذُوٓا۟ are separate nodes, and that test and line 28 of
<RepoLink repo="namaq" path="docs/quiz-ayah-branches.md" /> flip. `ayat.json` must be rebuilt
(`npm run quran:branches`), because `continues` decides the next-ayah leaves with `spell`. The plan's list of
ignored marks gains two entries.

**Fix B: the joining vowel (item 4).** The same pattern with `[\u064E-\u0650]$` would merge لَهُم and لَهُمُ, but it
cannot tell a joining vowel from a case ending: it would also merge ٱللَّهُ with ٱللَّهَ and خَلَقَ with خَـٰلِقُ.
A safe version needs the next word: drop a final short vowel only when the word after it starts with a hamzat
wasl (ٱ). That is a change to how `spell` is called, since it sees one word at a time today. Option D keeps
these apart on purpose, so this one waits for your call.

**Fix C: one key for pieces and quiz (item 5).** `pieces` and `branchQuestions` would walk `branch` (the marks
tree) instead of `phraseTree`. Then قَالَ رَبِّ إِنِّى is cut the way the page draws it, and the قال موسى question
opens with قَالَ مُوسَىٰ instead of «قَالَ». After fix A most of these mismatches disappear anyway, so fix C
matters only for real differences such as رَبِّ / رَبُّ.

**Item 6** needs no code if the plan's folding stands. **Item 7** shrinks from 151 to 56 with fix A, and the
rest are joining vowels (fix B) or real differences, which the quiz is right to ask.
