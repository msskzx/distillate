The records search box keeps its text in React state and writes it to the URL as `q`. Review
found that the box kept "highlight" after the reader followed a link to `/records`, because
the state was read from the URL only on mount.

The first fix compared the URL's `q` on every render with the last value the component had
written, and reset the box when they differed. Writing the regression test showed what that
did while typing: `router.replace` lands after the input's own re-render, so for a moment the
URL still holds the previous text, which differs from what was just written, and the box was
reset to it. A fast typist would have watched letters vanish.

The fix that held keeps a short list of values the component wrote. When the URL's `q`
changes to one of them, it is the component's own write arriving late and is ignored. Any
other value came from outside, so the box takes it. The check only reads the list and clears
it, so running it twice in one render changes nothing.

**Implications:** two-way sync between an input and the URL needs to know which changes are
its own. Test it with the URL lagging, not only with the URL updating at once.
