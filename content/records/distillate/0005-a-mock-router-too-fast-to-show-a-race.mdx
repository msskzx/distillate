Review reported that changing a filter right after typing could drop the typed text from the
URL. The test written for it typed, changed a filter, and checked the URL. It passed on the
fixed code, and it also passed on the old code.

The mock for `next/navigation` updated the search string inside `router.replace`, so the next
render already saw the new URL. In the browser, `replace` lands later, which is the whole bug.
The mock had removed the delay the test was about.

Making the mocked `replace` skip the update for the typing step put the delay back. The test
then failed on the old code, passed on the fix, and in passing exposed a second bug in the
first fix (see the record it builds on).

**Evidence:** <RepoLink repo="distillate" path="components/records/RecordSearch.test.tsx" />,
where the test calls `nav.replace.mockImplementationOnce(() => {})` before typing.

**Implications:** a test that has not been seen to fail on the old code has not been shown to
test anything. For timing bugs, the double has to keep the timing.
