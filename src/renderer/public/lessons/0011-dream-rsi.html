Dream-RSI: Replay Worlds for Recursive Self-Improvement

Core insight: Dream-RSI turns completed discovery histories into replay simulators. It can test many alternative exploration policies against recorded outcomes before spending money on new online searches.

Dream-RSI addresses a meta-level problem: not how to improve the solution generator directly, but how to improve the policy that decides which branches to explore, how much to parallelize, and when to stop.

1. The unusual “world model”

In Dreamer, a world model is a learned parametric simulator. Dream-RSI uses a different construction: a discovery tree records workspaces, decisions, candidate results, and scores. That finite tree becomes an empirical replay world.

2. What is being improved?

The policy chooses a batch of eligible tree nodes. A batch controls which branches to continue and how many workers run in parallel. The paper evaluates policies using a quality–cost tradeoff: find high-scoring candidates with fewer agent calls, while avoiding excessive sequential rounds.

Root workspace branches into recorded candidate attempts. A replayed policy chooses which recorded branches to reveal, possibly skipping a known dead end.

3. Online phase versus dreaming phase

PhaseWhat changes?What it costs
Online explorationThe agent generates and evaluates new candidates; the tree grows.Expensive agent calls and execution.
Offline dreamingA candidate policy traverses already-recorded branches.Mostly replay and scoring; no new candidate generation.
RedeploymentThe best replay-scoring policy becomes the next online policy.One new online rollout validates the improvement.

4. Why this is recursive self-improvement

Each online round expands the history. That larger history creates more replay worlds. Those worlds provide more feedback for revising the exploration policy. The revised policy then determines what new evidence enters the next generation of the simulator pool.

history = []
policy = initial_policy

repeat:
    tree = explore_online(policy)
    history.append(tree)
    candidates = revise_policy_by_replaying(policy, history)
    policy = best_replay_scoring_candidate(candidates)
The boundary

Replay is grounded, but not magical. It cannot reveal an outcome for a branch that was never recorded. A policy can overfit the historical trees, so fresh online exploration remains necessary.

5. Dream-RSI versus Dreamer

Both systems improve behavior through cheap internal “dreaming,” but their simulators differ:

  • Dreamer: learns a neural latent transition model that can generate new hypothetical states.
  • Dream-RSI: replays a finite tree of already-observed discovery outcomes and changes how that tree is traversed.

This makes Dream-RSI closer to planning over an empirical search graph than to learning a conventional physics-like world model.
